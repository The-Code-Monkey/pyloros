# Deny package code execution by default

Package lifecycle scripts are arbitrary code and do not run unless the exact package version is allowlisted with a reason, and allowed scripts run in a sandbox with no network and a read-only Store. Native packages must ship a prebuilt Platform Variant matching the running ABI. Published provenance attestations are verified when present, and an allowlisted script requires valid provenance. Trusting the registry's integrity hash alone was rejected because it proves what was published, not that publishing was honest; running scripts unsandboxed was rejected because install-time code is the primary supply-chain execution vector. The consequence is that some packages need an explicit opt-in, and v1 shells out to `cosign` for attestation verification, refusing script allowlists when it is unavailable.
