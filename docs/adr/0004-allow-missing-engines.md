# Allow packages that declare no Node.js version range

Pyloros originally required every package to declare an `engines.node` range that includes the exact running Node.js version, which rejected most of the npm ecosystem and forced Node type declarations to be vendored so the project could self-host. The Runtime Contract now treats a missing, empty, or unusable `engines.node` as compatible, while still refusing a package whose declared range excludes the running Node.js version. Mandatory declarations were rejected because they made the tool unusable for ordinary dependencies; vendoring type declarations was rejected because it bypassed the resolved tree rather than fixing the rule; ignoring declared ranges entirely was rejected because a package that explicitly says it does not support this Node version is a known incompatibility, not an unknown one. The consequence is that absence of compatibility metadata is accepted as unknown, so the contract is only as strong as the ecosystem's declarations.
